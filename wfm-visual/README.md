# WFM Command Center — Power BI custom visual

Workforce-management visual inspired by enterprise WFM tools (Verint-style intraday/daily/weekly views). **One visual, three view modes.**

## Planning page contents

| Section | What it shows |
|---|---|
| Header | Title, optional logo image, **Intraday / Daily / Weekly** switcher, prev/next/latest navigation |
| KPI strip | Volume vs forecast, forecast accuracy (1−WAPE), AHT vs forecast, service level, staffing gap, adherence — all vs configurable targets |
| Volume | Actual bars vs forecast line |
| AHT & service level | Forecast/actual AHT (left axis) + SL% (right axis) with target line |
| Staffing | Scheduled FTE bars coloured under / on-target / over vs required FTE marker |
| Heatmap | Day × hour staffing variance (7 days intraday, 14 days daily/weekly) |
| Interval grid | Verint-style table with conditional colouring |
| Agent roster | Avatars (https or `data:image/…` URL), adherence bars, initials fallback |

Click a bar or grid row to cross-filter other visuals. Inter is bundled (OFL); Segoe UI, DIN and Calibri are selectable.

## Pages

| Page | What it does |
|---|---|
| **Planning** | Intraday / Daily / Weekly dashboard (KPIs, volume, AHT & SL, staffing, heatmap, interval grid). Skill chips filter everything to one skill. Driver bands are drawn on the charts. |
| **Skills & Levels** | Skill-based planning table (forecast vs actual, accuracy, AHT, **SL vs per-skill target**, required vs scheduled FTE), skill × hour coverage heatmap, level mix per skill, level table. |
| **Teams & Agents** | **SLA per team** and **SLA per agent** with target ticks, SL trend by team, sortable agent table with avatars, team filter. |
| **Drivers** | Events, promotions, holidays, outages… Each driver has a period, volume % and AHT % impact, optional skill scope and status. Applied to **forecast volume, forecast AHT and required FTE** (actuals untouched). Timeline + list + editor. Baseline is shown dashed. |
| **Settings** | SL / accuracy / adherence targets, staffing tolerance, per-skill and per-team SL overrides, skill colours/priority/hide, level names/colours, heatmap hours, apply-drivers switch, write-back endpoint. |

Look & feel (font, theme, title, logo URL, colours, section toggles) stays in the Power BI **format pane**.

## Data model (field wells)

Agent-grain model, so totals never double count:

* **Plan rows** (agent blank): `interval × skill` with forecast volume, forecast AHT, required FTE.
* **Agent rows** (agent set): `interval × agent` with team, level, avatar URL, actual volume handled, actual AHT, scheduled FTE (1 per agent on shift), service level, adherence.

See `samples/wfm_intervals.csv` (generated by `scripts/generate-sample-data.mjs`). Only *Interval* is required; everything else enables more of the visual.

| Well | Notes |
|---|---|
| Interval (date/time) | interval start timestamp (required) |
| Skill / Queue, Team, Level / Tier, Agent / Team, Avatar image URL | optional groupings |
| Forecast / Actual volume | summed |
| Forecast / Actual AHT (sec) | volume-weighted |
| Required / Scheduled FTE | summed across rows, **averaged** across intervals in a bucket |
| Service level, Adherence | 0–1 or 0–100 accepted; SL volume-weighted, adherence averaged |

Intervals with no actuals (future) are excluded from variance/accuracy. Max 30,000 rows per refresh.

## Fallbacks & data health

The visual never goes blank silently. Problems show in a **Data health** bar under the header (auto-opens on errors; full list + data summary in *Settings → Data health*; toggle in the format pane under *Sections → Data health warnings*).

| Situation | Fallback | Warning |
|---|---|---|
| No Interval field / values aren't dates | Guidance card listing the fields to bind | error + how to fix |
| Interval has no time of day (all 00:00) | Switches to **Daily**, Intraday button disabled | warning |
| Negative volume/FTE, AHT ≤ 0 | Value ignored (treated as empty) | counted warning |
| Service level / adherence outside 0–100% (usually a *Sum* aggregation) | Clamped to 0–100% | warning + "set to Average" |
| Agent rows carrying forecast/required, duplicate rows | Still summed | double-counting warning |
| Rows with unreadable dates | Skipped | count |
| More than one 30k-row segment | Keeps fetching (up to 25 segments) | warning if still truncated |
| Skill/Team/Agent not bound | Page shows which fields to add; Planning keeps working | – |
| Period has no data | "No data in this period" + *Jump to latest* / *Zoom out* | – |
| Corrupt/out-of-range saved settings or drivers | Defaults / clamped values / bad drivers dropped | listed |
| Invalid driver (end ≤ start, impact out of range) | Not saved | inline message |
| Out-of-range setting | Not saved | inline message |
| Write-back URL not https or host not allowed; CORS/network failures | Friendly message, nothing breaks | inline |
| Broken logo/avatar URL | Logo hidden / initials shown | – |
| Unexpected exception while drawing | Error panel with **Reset view** | – |
| Very small visual | "Visual is too small" message | – |

Test them: `NODE_PATH=$(npm root -g) node test/health.cjs .tmp/shots-health`.

## Editions

Two packages are built from this repo: a **certified** edition (no network code, no privileges) and a **write-back** edition (optional endpoint). See `CERTIFICATION.md`. `npm run package:certified` / `npm run package:writeback`; prebuilt files are in `releases/`. The sections below on write-back apply to the write-back edition only.

## Saving settings & drivers (write-back)

Power BI visuals have no native database write-back, so there are two layers:

1. **Saved in the report (always on, certifiable).** Settings and drivers are stored in the visual's own properties via `persistProperties`, i.e. inside the `.pbix`. This works in Desktop and in the Service **edit** view; viewers in read-only mode can't persist changes.
2. **Your own system (optional).** Enable write-back in *Settings* and paste an https endpoint, e.g. a Power Automate "When an HTTP request is received" flow or an Azure Function. The visual sends:

```json
{ "schema": "wfm-command-center/1", "action": "save", "kind": "settings | drivers | forecast", "sentAt": "…", "payload": … }
```

`forecast` is the list of intervals changed by drivers: `{interval, skill, baselineForecast, adjustedForecast, baselineRequiredFte, adjustedRequiredFte}`, ready to land in a SQL/SharePoint/Dataverse table that feeds your forecast table. *Load from endpoint* POSTs `{"action":"load"}` and expects `{ "settings": {…}, "drivers": […] }` back.

Notes: saves are sent as a no-CORS `text/plain` POST (no preflight; the response is opaque, so check your flow's run history). *Load* needs the endpoint to return CORS headers — a Power Automate trigger may not, in which case front it with an Azure Function/APIM. The endpoint URL is stored in the report; don't put secrets in it beyond a signed-URL token you're happy for report authors to see.

> **Certification:** the endpoint feature needs the `WebAccess` privilege (hosts `*.logic.azure.com`, `*.api.powerplatform.com`, `*.azurewebsites.net`, `*.azure-api.net`), and certified visuals may not make external calls — so it exists only in the write-back edition.

## Build / test

```bash
npm install
npm run verify                           # tsc + eslint + banned-API scan + npm audit (all must pass)
npm run package:certified                # -> releases/…7F3A….pbiviz  (certification edition)
npm run package:writeback                # -> releases/…WB3A….pbiviz  (with optional endpoint)
node scripts/generate-sample-data.mjs    # -> samples/wfm_intervals.csv (28 days, 2 queues, 8 agents with avatars)
NODE_PATH=$(npm root -g) node test/harness.cjs .tmp/shots   # renders the built bundle in Chromium with a mock host
```

Import `dist/*.pbiviz` in Power BI Desktop (… → Import a visual from a file), load the sample CSV, and drop the columns into the wells (set measures to *Sum*, text/date fields to *Don't summarize*).
